# Exercise 05 - WebSocket Proxy

> Estimated time: ~30 minutes.

## Goal
Build a proxy that:
1. Intercepts (MITM) the WebSocket connection over HTTPS.
2. **Logs a dump of the handshake request** (`Upgrade: websocket`).
3. Establishes the connection with the WebSocket server for the client and
   relays the frames in both directions (goproxy does this automatically).

## Learning outcomes
- Understand the WebSocket handshake (HTTP Upgrade) and the `101 Switching
  Protocols` response.
- Serialize an HTTP request with `httputil.DumpRequest`.
- Use a custom upstream transport for a backend with a test certificate.
- See how goproxy bridges WebSocket frames after the handshake.

## Background (read before coding, ~5 min)
- **WebSocket handshake**: the client sends a normal HTTP `GET` with the
  headers `Connection: Upgrade` and `Upgrade: websocket`, plus a
  `Sec-Websocket-Key`. The server answers `101 Switching Protocols`; from
  that point the connection carries WebSocket frames, not HTTP.
  See: https://en.wikipedia.org/wiki/WebSocket
- **Why MITM**: the handshake happens over HTTPS, inside a CONNECT tunnel.
  Without MITM the proxy would not see it.
- **Dumping a request**: `httputil.DumpRequest(req, false)` serializes the
  request to bytes (headers only with `false`).
  See: https://pkg.go.dev/net/http/httputil#DumpRequest
- The backend uses `github.com/coder/websocket` for the echo server and the
  test client.

## Steps

### Step 1 - Understand the backend (`backend.go`)
Read `backend.go`. The echo server:
- upgrades the connection with `websocket.Accept(w, r, nil)`,
- reads messages in a loop and writes them back prefixed with `ECHO: `.
- returns a custom `*http.Transport` that trusts the httptest certificate
  (`ServerName: "example.com"`), returned as `echoTr`.

### Step 2 - MITM
To see the handshake over HTTPS, MITM every CONNECT:
```go
proxy.OnRequest().HandleConnect(goproxy.AlwaysMitm)
```
- https://pkg.go.dev/github.com/elazarl/goproxy#AlwaysMitm

### Step 3 - Custom upstream transport
The backend certificate is valid only for `example.com`, so the upstream
connection uses the custom transport `echoTr`:
```go
proxy.OnRequest(goproxy.ReqHostIs("localhost:11000")).DoFunc(func(req *http.Request, ctx *goproxy.ProxyCtx) (*http.Request, *http.Response) {
	ctx.RoundTripper = &roundTripper{tr: echoTr}
	return req, nil
})
```
The `roundTripper` type is already at the bottom of `main.go`.

### Step 4 - Dump the handshake
Log the handshake request:
```go
proxy.OnRequest().DoFunc(func(req *http.Request, ctx *goproxy.ProxyCtx) (*http.Request, *http.Response) {
	dump, err := httputil.DumpRequest(req, false)
	if err != nil {
		log.Printf("handshake dump error: %v", err)
	} else {
		log.Printf("WebSocket handshake request dump:\n%s", dump)
	}
	return req, nil
})
```
- https://pkg.go.dev/net/http/httputil#DumpRequest

### Step 5 - Run the demo client
The test client at the bottom of `main.go` dials `wss://localhost:11000`
through the proxy, sends two messages and reads the echoes. Once goproxy
receives the `101 Switching Protocols`, it relays the frames in both
directions automatically.

## Check your understanding
1. Which HTTP headers make the request a WebSocket handshake? How would you
   detect it in a handler?
2. Why is `DumpRequest` called with `false`? What would change with `true`?
3. Why can't the proxy see the handshake without MITM?
4. After the `101`, why doesn't goproxy parse the frames as HTTP?
5. The client uses `InsecureSkipVerify: true`. What is it skipping, and why
   is it acceptable in this exercise?
6. What would happen if the `Sec-Websocket-Key` header were stripped before
   reaching the server?
