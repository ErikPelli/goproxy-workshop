# Exercise 01 - API Proxy

> Estimated time: ~30 minutes.

## Goal
Build a proxy that:
1. Intercepts (MITM) HTTPS traffic.
2. Recognizes API requests via the `X-Random` header.
3. Applies **rate limiting** (1 request per minute per IP), responding
   `429 Too Many Requests` when the limit is exceeded.
4. Enriches the response with an `X-Random` header containing a random
   number generated by a backend.

## Learning outcomes
- Understand what a forward HTTP proxy does and what a `CONNECT` request is.
- Use goproxy's `OnRequest` / `OnResponse` handlers.
- Enable Man-in-the-Middle with goproxy.
- Implement rate limiting with `httprate`.
- Use a certificate cache to avoid re-signing certificates.

## Background (read before coding, ~5 min)
- **HTTP proxy**: the client sends the full URL in the request line
  (`GET http://example.com/ HTTP/1.1`) and the proxy forwards it.
  For HTTPS the client first opens a tunnel with `CONNECT host:443`, then
  speaks TLS inside it. A proxy that only tunnels cannot see the payload.
- **MITM**: to inspect HTTPS, the proxy terminates the TLS itself and opens
  a second TLS connection to the target, presenting a certificate signed by
  a CA that the client trusts.
- **goproxy handlers**: `proxy.OnRequest(...)` registers callbacks run before
  forwarding the request; `proxy.OnResponse(...)` runs on the response.
  - https://pkg.go.dev/github.com/elazarl/goproxy#ProxyHttpServer.OnRequest
  - https://pkg.go.dev/github.com/elazarl/goproxy#ProxyHttpServer.OnResponse

## Steps

### Step 1 - Certificate cache (`cache.go`)
The proxy generates a TLS certificate for each intercepted host. Generating
a certificate is expensive, so `goproxy` caches them through the `CertStorage`
interface (`Fetch(hostname, gen)`).

Implement `Fetch`:
- If `hostname` is already in the map, return it.
- Otherwise call `gen()`, store the result, and return it.
- Protect the map with the mutex (RLock for reads, Lock for writes).

Why a mutex? A proxy handles many requests concurrently.
See: https://pkg.go.dev/sync#RWMutex

### Step 2 - Enable MITM (`main.go`)
Register the handler that MITMs every CONNECT:
```go
proxy.OnRequest().HandleConnect(goproxy.AlwaysMitm)
```
- https://pkg.go.dev/github.com/elazarl/goproxy#AlwaysMitm
- Why: without MITM the proxy would only see `CONNECT` and never the HTTP
  request that flows inside the tunnel.

### Step 3 - Rate limiting
Create the rate limiter (1 request per minute):
```go
rateLimiter := httprate.NewRateLimiter(1, time.Minute)
```
- https://pkg.go.dev/github.com/go-chi/httprate
- The handler that uses it is already provided. `mockResponseWriter` is
  provided too because `OnLimit` needs an `http.ResponseWriter` to write the
  error response into.

### Step 4 - Enrich the response
When the API response is `200`, query the backend (`http://localhost:11000`),
decode the JSON and set the `X-Random` header:
- `http.NewRequestWithContext`: https://pkg.go.dev/net/http#NewRequestWithContext
- `io.ReadAll`: https://pkg.go.dev/io#ReadAll
- `json.Unmarshal`: https://pkg.go.dev/encoding/json#Unmarshal
- The backend returns `{"number": 0..9}` (type `randomResponse` in `backend.go`).
- Build the query as `http.MethodGet` and read the number into a `randomResponse`.

## Check your understanding
1. Why does the proxy need MITM to see HTTPS requests, and what does it see
   without it?
2. What does `CONNECT host:443` do, and why can't the proxy read the data
   inside the tunnel it creates?
3. Why is a mutex needed in `CertStorage`? What could go wrong without it?
4. `OnRequest(...).DoFunc` returns `(req, resp)`. What happens if you return
   a non-nil `resp`?
5. Why is the rate limiter keyed by client IP (`strings.Cut(req.RemoteAddr, ":")`)
   rather than by user?
6. In `Step 4`, why must the response pass through `proxy.OnResponse(...)` and
   not be modified in `OnRequest`?

## Verify
Run the proxy:
```sh
go run .   # from exercises/01_api_proxy
```

> Tip: open `TEST.md` and run the curl commands it contains: the expected
> output is recorded there, so you can check whether your proxy matches it.

In another terminal:
```sh
curl -v --proxy http://localhost:10999 --cacert goproxy_ca.pem \
  --header "X-Random: true" https://fake-url.com/
```
- First request → `HTTP/1.1 200 OK` + header `X-Random: <n>` + body `Correct response`.
- Requests within the same minute → `HTTP/1.1 429 Too Many Requests`.
- Request without `X-Random` → `HTTP/1.1 401 Unauthorized`.
